CSS Without a Framework

Lesson 3 · css · ~6 min

CSS has a reputation as the part of the stack you fight until you give up and install a framework. That reputation was earned around 2010 and has been obsolete for years. Modern CSS — variables, flexbox, grid, media queries — solved most of what the frameworks were invented to paper over. This site's entire design is one stylesheet, written to be read. Open it alongside this lesson; it's the worked example.

Mobile-first is a way of thinking, not a buzzword

Write your plain CSS rules for the smallest screen. Then, inside @media (min-width: ...) blocks, add the few adjustments larger screens need. This site's stylesheet has exactly one such block, and it changes two things: padding and font size.

The direction matters. A phone layout is usually the simple one — a single column, content in order. Start there and you add complexity for big screens. Start desktop-first and you're undoing complexity on small screens, which is where most broken mobile sites come from.

The boring truth: the single highest-impact line of mobile CSS isn't CSS. It's the viewport meta tag in the HTML head: <meta name="viewport" content="width=device-width, initial-scale=1">. Without it, phones render your page 980px wide and zoom out, and nothing else you do matters.

Custom properties: theming without tooling

CSS variables (officially "custom properties") are the built-in replacement for what once required a preprocessor. Define values on :root, use them anywhere: 

:root {
  --accent: #0b5d8a;
}

a {
  color: var(--accent);
}

Because they're live values, not compile-time substitutions, you can redefine them inside a media query — which is exactly how this site's dark mode works. One block redefines the color variables when the device prefers dark, and every rule that uses them follows automatically: 

@media (prefers-color-scheme: dark) {
  :root {
    --bg: #16191d;
    --text: #e6e9ec;
  }
}

If your phone is in dark mode, you're looking at the result right now. Total cost: one media query. No toggle button, no JavaScript, no theme framework — the operating system already knows the user's preference, and CSS can simply ask.

Three defaults that make text readable

Most of "good design" on a content site is typography, and most of typography is three decisions:

  • Line length: max-width: 65ch on the body. The ch unit is the width of a character, so this caps lines at roughly 65 characters — the comfortable reading range.
  • Line height: around 1.5–1.6 for body text. The browser default (about 1.2) is too tight for paragraphs.
  • Font: you don't need a webfont. The system font stack (system-ui and friends) costs zero bytes and looks native everywhere. This site pairs it with Georgia — a serif that has shipped with every device since the nineties — for body text.

When you actually need layout

Flexbox handles one-dimensional arrangement — a row or a column. The previous/next links at the bottom of this page are a flexbox with justify-content: space-between, which pushes them to opposite edges: a layout task that once required float hacks, solved in two lines. Grid handles two-dimensional layout; this site doesn't need it yet, which is itself a boring-stack lesson — don't reach for the more powerful tool before the problem shows up.

Check yourself

What does "mobile-first" mean mechanically, in the stylesheet?

Plain (unqualified) rules describe the small-screen layout, and @media (min-width: ...) blocks add adjustments for larger screens — so complexity is added as screens grow, never undone as they shrink.

How does this site support dark mode with no JavaScript?

Colors are defined once as custom properties on :root, and a prefers-color-scheme: dark media query redefines them. Every rule using var(--...) updates automatically.

Why max-width: 65ch instead of a pixel value?

The ch unit is based on character width, so the limit tracks what actually matters for readability — characters per line — and stays correct if the font or its size changes.
