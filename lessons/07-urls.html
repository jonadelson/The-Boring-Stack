URLs Are User Interface

Lesson 7 · http · ~7 min

The URL is the most successful interface element ever shipped. It works in a text message, an email, a sticky note, a QR code, a podcast ad read aloud. It's the only part of your app that appears in every screenshot. And it's the web's original superpower — the thing native apps still can't really do: hand anyone, on any device, a small string that opens exactly the right screen. This lesson is about treating that string as a designed surface instead of an accident.

The two parts lesson 5 skipped

/search?q=postgres&sort=new#results
└──┬──┘└────────┬─────────┘└───┬──┘
 path        query          fragment
  • The query string — key-value pairs after the ?. You met it in the forms lesson: it's where GET forms put their fields.
  • The fragment — everything after #. It never reaches the server; the browser uses it to scroll to the element with that id. Add id="pricing" to a heading and /about#pricing deep-links straight to it, for free.

Good URLs are readable, guessable, and hackable

Compare:

/lessons/06-forms.html
/index.php?page_id=2847&ref=nav&sess=8f3a2c

The first tells you what you'll get before you tap. It's guessable — you could type /lessons/ and expect something sensible — and hackable in the good sense: trim it to /lessons/05-http.html or up to the site root and you land somewhere reasonable. The conventions that produce URLs like it are boring and simple: lowercase, hyphens between words, nouns organized in a hierarchy, and no implementation details. That .php in the second example is the server's private business leaking into a public, permanent interface — the moment you switch languages, every bookmark breaks.

The boring truth: in 1998 Tim Berners-Lee wrote an essay titled "Cool URIs don't change." A URL is a promise: people bookmark it, cite it, link it from places you'll never find. Design URLs you can honor for a decade — and when you must move something, answer the old URL with a 301 redirect (lesson 5's "go elsewhere" family) rather than a 404. Breaking links is losing data that other people were storing for you.

The URL is a state manager

Here's the idea that connects this lesson to the React one. A URL with a query string — /search?q=postgres&sort=new — is application state, stored in the most boring database available: the address bar. Put state there and a pile of features appear without code: refresh keeps your place, the back button is undo, bookmarking saves the view, and sharing sends your exact screen to someone else's phone.

Now you can name a familiar SPA bug precisely: filters set, three tabs deep, refresh — everything gone, because the state lived in JavaScript variables and the URL still said /dashboard. The app broke its half of the URL bargain. Whatever rung of the ladder you're on, the discipline holds: if a user could want to share, bookmark, or refresh into a view, that view belongs in the URL.

Designing this site's URLs

Even this small site made URL decisions, and one of them is already regrettable — instructively so. The numbered filenames (06-forms.html) encode ordering into the address. If a new lesson ever belongs between HTTP and forms, the choice is renumbering (breaking every existing link — see the callout above) or living with misordered numbers. State leaked into an identifier: the exact mistake from the state-design arc, in filename form. A wiser scheme was available all along: /lessons/forms/ — stable name, ordering left to the index page, and the .html extension gone too. When the phase 3 server arrives and routing becomes code we control, migrating to that scheme — with 301s from the old URLs — will make a perfect worked example.

Check yourself

What's the difference between the query string and the fragment?

The query string (?key=value) is sent to the server as part of the request. The fragment (#section) never leaves the browser — it scrolls the page to the element with that id.

You're restructuring a site and moving pages. What do the old URLs owe their bookmarkers?

A 301 permanent redirect to the new location. Cool URIs don't change — and when they must, they forward their mail instead of returning 404.

A dashboard loses all its filter settings on refresh. Diagnose it in this lesson's terms.

View state that users would want to refresh, share, or bookmark was kept in JavaScript variables instead of the URL. The fix is putting the filters in the query string, making the address bar the state manager.

What's wrong with numbered lesson filenames like 06-forms.html?

They encode ordering into a permanent identifier. Inserting a lesson means either renumbering (breaking published links) or accepting wrong numbers — ordering belongs in the index, and stable names like /lessons/forms/ belong in the URL.
