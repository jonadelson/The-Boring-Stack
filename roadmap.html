The Full Roadmap

the curriculum and the app, which are the same thing

This site grows in phases, and each phase begins only when the current stack genuinely hurts. That's not project management — it's the pedagogy. Every technology arrives with its justification attached, because you'll have felt life without it first.

Phase 1 — Static site (current)

The app: hand-written HTML and CSS on GitHub Pages. No build step, no JavaScript.

Lessons: why boring ✓ · semantic HTML ✓ · CSS without a framework ✓ · when do you actually need React? ✓ · HTTP: what happens when you tap a link ✓ · forms, the most underrated element ✓ · URLs as design ✓ · images and media ✓ · accessibility fundamentals

Phase 2 — JavaScript sprinkles

The pain that triggers it: the quizzes forget every answer the moment you leave the page.

The app: quizzes that remember your answers, a review queue, a streak — vanilla JavaScript and localStorage, added as progressive enhancement so every page still works without it.

Lessons: the DOM and events · JavaScript the language (the parts that matter without a framework) · localStorage · progressive enhancement as a discipline · implementing spaced repetition (SM-2 in ~30 lines)

Phase 3 — A server and Postgres

The pain: progress doesn't sync between phone and laptop, because localStorage lives in one browser.

The app: a small Node server, server-rendered pages, progress in Postgres. Deployed early in the phase, not at the end — running code beats perfect code.

Lessons: writing an HTTP server with (almost) no framework · SQL from zero to JOINs · schema design: cards, reviews, intervals · migrations · transactions and constraints · indexes and reading EXPLAIN · server-side templating

Phase 4 — Authentication and security

The pain: the server is on the public internet and progress needs to belong to you.

The app: accounts, login, per-user data, password reset. Security learned by building it, not reading about it.

Lessons: cookies and sessions · password hashing (and why not SHA-256) · SQL injection · XSS and escaping · CSRF · security headers · rate limiting · email delivery (a gloriously boring technology of its own)

Phase 5 — Operations

The pain: it's a real app now, and you're responsible for it at 3am.

Lessons: a VPS and systemd · DNS for real · TLS and Let's Encrypt · nginx as reverse proxy · logs: what to write, how to read · backups and restore drills (an untested backup is a wish) · cron · measuring performance before optimizing

Phase 6 — Electives

Once the platform exists, each of these is a self-contained lesson-plus-feature:

  • SQLite — when it beats Postgres
  • htmx and HTML over the wire — climbing rung 3 of the ladder on purpose
  • HTTP caching and CDNs
  • Full-text search in Postgres — before reaching for Elasticsearch
  • Job queues in Postgres with SKIP LOCKED — before reaching for Redis
  • WebSockets versus server-sent events
  • Testing the boring way
  • One deliberate island: a rich client-side widget (an interactive SQL playground) as a worked example of framework-where-it-counts

The application-architecture arc

A three-lesson elective on the skills rich client apps demand — framework-agnostic on purpose, and best taken after phase 3, because its central claim needs schema-design experience to land: client state design and database schema design are the same discipline.

  • State design — essential versus derived state, one source of truth per fact, normalize-don't-duplicate: the schema lessons replayed in the browser
  • Component boundaries — components as functions: data in, events out; where to split, what to colocate, and why most component-design pain is interface-design pain
  • Server state versus UI state — why treating a server cache as client state is the root of most SPA bugs, and what the popular data-fetching libraries actually solved

The three rules: no layer is added until its absence hurts. Something ships every week. And the site eats its own cooking — by phase 3, the spaced-repetition engine will be quizzing its builder on the SQL that powers the spaced-repetition engine.
